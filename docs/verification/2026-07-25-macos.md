## External-model compatibility probes

Ollama 0.32.3 and `qwen3:4b-instruct` were tested through Codex CLI 0.145.0 on the same machine.

1. A direct Ollama API fixture confirmed that this model can emit a simple function call.
2. Standard plugin mode did not reach the model because this Codex/provider combination rejected MCP `namespace` tools.
3. `CODEX_SEARCH_BRIDGE_CLI_ONLY=1` removed the MCP namespace and exposed an intentional empty MCP tool list.
4. The bundled Skill and an additional prompt containing the exact runner path and exact `exec_command` / `write_stdin` sequence were both tried.
5. The model still returned a no-web-capability refusal without issuing a command-tool call.

Result: this is a recorded negative compatibility test, not an end-to-end success. The Bridge CLI runner and its isolated distribution are covered independently, but autonomous use by `qwen3:4b-instruct` is not claimed. The observed failure is at the outer model's command-tool selection step; no Bridge research process was invoked by that model.

### `qwen3.5:4b`

The newer 4B model could call Codex standard command tools, which validated the reason for adding CLI-only transport. The probe then exposed and drove fixes for three concrete protocol issues:

- `tty: true` is required to keep stdin open;
- some model/tool combinations double-escape the final LF;
- a nonempty `write_stdin` can yield before research completes, so the model must poll the same session and must not treat readiness markers or PTY echo as results.

After those fixes, deterministic CLI tests and isolated-bundle smoke tests passed. The model-specific run still did not pass end to end: without outer sandbox network access the nested worker failed; with network enabled the model either deviated from the prescribed runner command or treated a readiness marker as final data and fabricated unsupported dates and counters. That fabricated answer was rejected and is not stored as sample evidence.

Result: negative for autonomous use. The command transport works, but this model/version did not reliably orchestrate it.

### `qwen3.5:9b`

The 9B model loaded and issued the exact initial runner command, but generation on the 16 GB test host caused severe memory pressure and sub-token-per-second output. The probe was stopped before a research result at the user's request, all Ollama/llama/Codex child processes were terminated, and the temporary Codex home containing a copied `auth.json` was deleted. No compatibility outcome is claimed.
